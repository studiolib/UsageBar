# アーキテクチャ

この文書は、UsageBar の構成と、Claude / Codex の利用量データをどのように正規化して macOS メニューバーアプリとして表示しているかをまとめたものです。

## 目的

UsageBar は意図的に小さなアプリとして設計しています。

- Claude と Codex の利用制限残量を macOS のメニューバーから確認する
- 推定値ではなく、各サービスから取得できる利用量データを優先する
- グラフ、請求履歴、無関係な分析機能は扱わない
- UIにアカウント識別子を表示しない
- macOS のライト / ダークモードに追従する

## アプリ構成

Swiftターゲットは2つに分かれています。

```text
UsageBar       macOSアプリ、メニューバー項目、ポップオーバーUI
UsageBarCore   ドメインモデル、設定、プロバイダ、パース、永続化ヘルパー
```

アプリターゲットは AppKit / SwiftUI 連携を担当します。

- `NSStatusItem` で2本バーのメニューバーアイコンを描画
- `NSPopover` で SwiftUI のポップオーバーを表示
- Dockに表示されないアクセサリアプリとして動作
- 設定された更新間隔に応じて利用量データを更新

Coreターゲットはプロバイダに依存しないロジックを担当します。

- 利用量のドメインモデル
- 設定の保存
- Claude / Codex プロバイダ
- レスポンスの柔軟なパース
- Keychain ヘルパー

## メニューバーアイコン

メニューバーアイコンは2本の横バーで構成します。

- 上: Claude の週間残量
- 下: Codex の週間残量

メニューバーサイズでも読みやすいよう、アイコン内には数字や文字を表示しません。

## ポップオーバーUI

ポップオーバーには次の要素があります。

- アプリ名、最終更新時刻、手動更新ボタン
- Claude の利用量カード
- Codex の利用量カード
- 設定ボタンと終了ボタン

各利用量カードでは次を表示できます。

- プロバイダ名
- プラン名
- 短時間制限が取得できる場合は短時間制限
- 週間制限
- 残量パーセント
- リセット日時
- リセットまでの残り時間
- 取得時刻
- 公式の使用量確認ページへのリンク

アカウント名、メールアドレス、アカウントIDはUIに表示しません。

## ドメインモデル

各プロバイダのレスポンスは共通のドメインモデルへ正規化します。

```swift
struct UsageSnapshot {
    let provider: Provider
    let accountLabel: String
    let planLabel: String
    let capturedAt: Date
    let shortWindow: UsageWindow?
    let weeklyWindow: UsageWindow?
}

struct UsageWindow {
    let title: String
    let usedPercent: Double
    let remainingPercent: Double
    let resetDescription: String
    let resetAt: Date?
}
```

`shortWindow` と `weeklyWindow` はどちらも optional です。サービス、プラン、現在の利用状態によって、返ってくる制限ウィンドウが異なるためです。

重要なケース:

- Claude は週間制限だけを返し、5時間制限を返さないことがある
- Claude は5時間制限の使用率だけを返し、リセット時刻を返さないことがある
- Codex は週間制限だけを返すことがある
- リセット時刻がないだけで、有効な利用量ウィンドウを破棄しない

## パーセントの正規化

UsageBar は内部的に使用量を `usedPercent` として扱います。

正規化ルール:

- `0 < value < 1` は比率として扱い、100倍する
- `1` は `100%` ではなく `1%` として扱う
- `1` より大きい値はパーセントとして扱う
- 最終値は `0...100` に丸める

表示する残量は次の式で求めます。

```text
remainingPercent = 100 - usedPercent
```

## Claudeプロバイダ

Claude資格情報は次の順で読み取ります。

1. UsageBar 自身の Keychain 項目
2. ユーザーが明示的に再認証を実行した場合のみ、既存の Claude Code 資格情報を UsageBar の Keychain へ取り込み

通常更新では UsageBar 自身の Keychain だけを利用します。アプリ側のキャッシュがない場合、バックグラウンドで Claude Code の資格情報を自動取り込みせず、認証が必要な状態として扱います。

Claude の利用量レスポンスは形が変わる可能性があるため、ウィンドウ名、使用率、リセット時刻、期間のキー名に対して柔軟にパースします。

## Codexプロバイダ

Codex の利用量取得は、ローカルの Codex CLI 認証状態をもとに行います。

通常更新では UsageBar 自身の Keychain 項目だけを利用します。既存の Codex CLI 資格情報の取り込みは、設定画面でユーザーが明示的に再認証を実行した場合だけです。取り込んだ資格情報と更新後の資格情報は UsageBar の Keychain にのみ保存し、Codex CLI の認証ファイルへは書き戻しません。

Codex が1つの制限ウィンドウだけを返す場合、UsageBar はそれを週間制限として扱います。

Codex のレスポンスも、CLI/APIバージョンによる形の違いに備えて柔軟にパースします。

## 外部サービスへの依存

UsageBar は、Claude Code / Codex CLI が管理するローカル認証状態を入力として、各サービスの利用量取得とトークン更新に必要な通信を行います。利用量取得に使うエンドポイントやレスポンス形式は、安定した公開APIとして保証されていない場合があります。

認証では、公開クライアント互換のフローに必要な非秘密のクライアント識別子を使う場合があります。APIキーやクライアントシークレットをアプリに埋め込む設計ではありません。一方で、提供元の仕様、認証方式、利用規約、運用方針が変われば、取得処理を修正または停止する必要があります。

Codex CLI と UsageBar は別々の Keychain 項目を使いますが、同じアカウントの認証状態をもとに利用します。サービス側のリフレッシュトークン更新仕様によっては、両者を並行利用したあとに、どちらかで明示的な再認証が必要になる可能性があります。

このため、プロバイダごとの通信処理は `UsageBarCore` に閉じ込め、UIや利用量の共通モデルから分離しています。外部仕様の変更時はプロバイダ実装とテストを優先的に見直します。

## エラー処理

UsageBar はプロバイダ状態とスナップショットを分けて扱います。

- `fresh`: 最新の取得結果を表示している状態
- `stale`: 更新に失敗した状態。前回成功したスナップショットがあれば、その取得時刻とともに表示する
- `authRequired`: UsageBar の資格情報がなく、設定画面から明示的な再認証が必要な状態

レート制限、パース失敗、利用量ウィンドウの欠損などは、`stale` 状態に紐づく失敗理由として保持します。

不足している値を推測で埋めることはしません。更新失敗後に前回成功したスナップショットを表示する場合も、元の取得時刻が分かるようにします。

## 設定

現在の設定項目:

- 更新間隔

通常更新と手動更新は常に UsageBar 自身の Keychain 項目だけを使用します。Claude Code / Codex CLI の資格情報は、設定画面の再認証操作からだけ取り込みます。以前のClaude Keychain設定が保存されている場合も、起動時に削除します。

## パッケージング

ローカルパッケージングでは次の `.app` 構造を作成します。

```text
UsageBar.app/
  Contents/
    Info.plist
    MacOS/
      UsageBar
    Resources/
      AppIcon.icns
```

`LSUIElement = true` により、アプリはDockに表示されません。

ローカルパッケージングスクリプトは開発ビルド用です。公開配布では Developer ID 署名、hardened runtime、notarization、staple 済みのリリース成果物が必要です。

## テスト

Coreテストでは主に次を確認します。

- Claudeレスポンスのパース
- Claudeの5時間制限でリセット時刻がないケース
- Claudeの整数使用率をパーセントとして扱うケース
- Claudeの週間制限のみのケース
- Codexレスポンスのパース
- Codexの単一ウィンドウを週間制限として扱うケース
- トークン更新フロー
- 資格情報がないケース
- 設定の保存
- Storeのマージ挙動
- Keychain保存ポリシー

テスト実行:

```sh
swift test
```
